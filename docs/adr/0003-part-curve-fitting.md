# ADR 0003: 部品ごとに参考画像の線を測り、表情を共有する描画に当てはめる

- 状態: **承認**（2026-11-24。owner 承認。非出荷の校正試作から開始）
- 関連: [ADR 0001](0001-manga-face.md) D2・D3・D6・D7、[ADR 0002](0002-reference-guided-faces.md) D2〜D9
- 対象: 正面の顔。最初の試作は、条件を満たす採用済み参考の髪と、無表情・笑顔・驚きの3表情。候補はボブの前髪と顔にかかる房。長い巻き髪は採用済み参考が揃った場合の非出荷の比較候補。

## 背景

髪全体の幅と長さを合わせても、顔にかかる房の位置、巻く間隔、重なりが違えば、同じ髪に見えない。試作では、巻き髪の制御点や線を増やしても、対応する房が参考画像のどこを通るかを測っていなかった。反対に、画像ごとに一枚絵をなぞると見た目は合わせやすいが、別の表情に同じ髪や顔を再利用するには、部品の対応と位置合わせが必要になる。

ADR 0002 D4 のランドマークは大きさと位置、D5 の墨の距離は全体の見た目を測る。今回はその段 b の前半に、**意味を付けた輪郭や線に対する部品ごとの当てはめ**を加える。D5 の中立を先に当て、表情差分をあとで求める方針を維持する。D2 の参考の採否、D6 の出荷条件、D8 の評価と owner 確認は適用する。

## 提案

### D1. 見えている線を部品ごとに記録する

元マスの座標で、部品 ID、左右、境界・中心線・塗りの区別、始点から終点の向き、見えている区間を記録する。房には根元と毛先、見える区間の幅、前後関係を付ける。ツヤは房 ID と房の中心に対する位置を持たせる。目は上下まぶた・目頭・目尻、口は上下の境界と口角を別にする。

自動ベクター化は D3 の墨の境界や領域を拾う補助に使う。線の両縁から意味のある中心線が自動で得られるとは仮定せず、試作では Codex が版固定した画像入力 AI に区間のラベルと少数の点を読ませる。別実行で独立に読み、最初の結果を渡さない。人は読みの監査と参考の採否を担当し、座標を手で補完しない。ADR 0002 D4・Q8 の AI 計測を維持する。読めない線は保留し、人による注釈へ切り替える場合は owner の承認を得て ADR を改訂する。隠れた区間、境界が判別できない区間、対応する房が不明な区間には理由を記録し、画像からの損失に含めない。前後は画像で確認できる対だけ記録し、循環する指定は入力エラーにする。

記録には参考 ID、元マス位置、画像と来歴の SHA-256、注釈形式の版、担当を持たせる。描画用の曲線とは別ファイルにする。検証用には生え際、頬の前、肩の前の少なくとも1区間ずつを独立に注釈し、差が出た区間は Codex が原画像で対応の根拠を確認し、同じ指示で再計測する。合意できない区間を欠測とし、owner には未確認の箇所を示す。肩に届かない髪では肩の区間を適用外と記録する。

### D2. 部品を当てはめてから、合成結果を確かめる

1. D5 段 a に沿い、中立のランドマークから位置、縮尺、既存パラメータを求める。画像の差を消すための局所的な変形は使わない。
2. 髪は、分け目、房の始終点、幅と先細り、巻きの間隔と大きさ、前後を持つコード上の候補を使う。房数と重なり順の候補を先に絞る。同じ髪の候補を当てはめ中に増殖させず、比較した候補と採否を記録する。試作では既存候補と、巻く間隔の変化を表せる候補を比較する。
3. 候補描画は、モデルの房 ID、左右、付け根の順序、中心線、レンダー後の可視区間を試作ツールに返す。左右と生え際の区分ごとに、付け根の順序を保つ一対一の対応を探索前に固定する。同じ区分に複数候補があれば、対応する房の数を最大にし、その中で正規化した付け根位置の総距離が最小の対応を選び、同点は ID 順で確定する。対応表は候補ごとに保存し、探索中は変えない。対応なしの参考の可視房と、余分に見えるモデルの房には被覆不足として罰則を与える。
   - 可視区間の両端を対応させ、根元から毛先に向けた正規化弧長で等間隔にサンプリングし、順序付き点距離を測る。既知の区間に対して各方向の被覆率も測る。基準側で見えているのに描画側で短縮や隠れが生じた部分は被覆不足とし、対応距離を計算できないときは最大誤差に数える。基準側の欠測とモデル側だけの隠れを区別し、分母は探索開始前に固定する。
   - 試作での初期規則は、測定区間ごとに8点以上、距離と被覆を各半分、区間の重みは参考の可視弧長に比例とする。距離は中立の相似変換でモデル単位に換算し、採用した許容距離 τ の2倍で打ち切って 0〜1 の損失にする。被覆不足は両方向の未被覆弧長を、同じ参考の可視弧長で割った値の平均とし、1で打ち切る。余分な可視房も未被覆弧長に加える。房の幅の誤差は対応断面で別に報告する。確認済みの前後が逆転した候補は棄却する。τ は独立読みの差を校正データで確認して比較前に固定する。
4. その上で、意図しない穴・重なり・線のはみ出しを、合成後のパーツ画像と D5 段 b の墨の距離で確認する。部品の距離は、見える前景・背景の順を検査する代用にしない。まず後述の事前固定した判定に従い、owner が見た目を確認する。
5. 同じ候補で差が残る場合は、失敗箇所を寸法、線の途中の変化、房の数や前後関係のどれで説明できるかを調べる。たとえば、同じ房で上下の巻きの間隔が異なる例に対し、間隔の一定モデルと、上部・下部で間隔を変えられるモデルを同じ入力で比較する。自由な制御点列で個別参考を覚えさせる方法は候補に含めない。

試作では現行描画、同じ描画を部品距離で当てはめた版、描画ルールを1つ増やした版を同じ条件で比較する。探索法の置き換えはこの提案の対象外とし、連続・離散の扱い、最後の丸めと再評価、全表情の検証は ADR 0002 D5 に従う。

### D3. 共通の人物を固定し、表情差分を当てはめる

シートの各マスは中立で求めた縮尺を固定し、平行移動だけを推定する。追加の位置合わせ点には、左右の耳の付け根、分け目、首の付け根など、表情プリセットで固定される部位を使う。D4 の非中立の13点へ混ぜず、この試作専用の別フィールドにする。目尻、口角、眉は位置合わせから外す。離れた位置にある2点以上が両マスで同定できる場合だけ推定する。独立読みから事前に固定した残差許容値を超えるマスは、角度や大きさのずれとして理由をつけて除外する。位置合わせ後に髪・輪郭・首を固定し、各表情では目・眉・口の差分だけを当てはめる。

試作は中立の形から開始し、笑顔と驚きを当てる。余裕があれば画像上で未使用の怒りを使い、既存の表情プリセットをそのまま適用した結果を別枠で確認する。試作の3表情への当てはめは、未見人物や未見表情への一般化の証明としては扱わない。

### D4. 非公開の計測と製品への反映

なぞった SVG、注釈座標、パーツのマスク、参考ごとの当てはめ値、比較画像、重ね合わせ画像は ADR 0002 D6・D9 の扱いに従う。試作には R1 の generate.py で生成し、R2 で owner が accepted と domain を記録した参考だけを使う。過去の ChatGPT 生成比較（ai-0003〜0005）は生成・採用条件が揃っていないため、この提案の試作入力や採否の根拠から外す。

出荷する図形は独自にコード化する。生成曲線は整理・単純化・平均化しても出荷物に含めない。房の形のように個別画像を再構成できる点列やパラメータを製品の既定値に埋め込まない。公開の寸法範囲、既定値、プリセットは、方向と項目ごとに欠測のない独立した参考10件以上から D6 の丸めた集計値を作る。参考1件の試作で決められるのは、計測とモデル比較の手順が動くかどうかまで。既存の手調整した比較レンダラーと個別定数表は非出荷の作業記録として扱う。

| 成果物 | 保存と共有 |
| --- | --- |
| 元画像、注釈の曲線、トレース SVG、パーツマスク、個別フィット、比較と重ね合わせ | ADR 0002 D9 の非公開ストア、または本人だけが読めるディレクトリとファイル。公開 PR・Issue・CI には添付しない |
| 出荷するコードの図形、条件を満たす集計と評価の要約 | D6・D8 に従い公開可。公開 PR の前後画像にはコードから描画した絵だけを載せる |

試作コードは既存レンダラーを利用できる場合も非出荷の道具に置く。新しい髪型を src/ や golden に足す場合は、ADR 0001 の型と工程への変更を先に合意し、U2・U3 の owner 確認と ADR 0002 R9 の前提に従う。

## 試作の確認

- **非公開の比較**: 同じ縮尺で「元画像」「部品をなぞったSVG」「当てはめたSVG」「現行SVG」を並べる。無表情では房単位の重ね合わせも示す。3表情は元画像の大きさと、ADR 0001 D7 の舞台サイズで確認する。
- **計測と精度**: 注釈に使った区間と、当てはめに使わない独立の区間を分ける。部品距離は中立の相似変換でモデル単位に換算し、欠測と対象区間も報告する。注釈を分けた同一シートは計測の再現性の確認に使う。描画ルールの採否には設計に使っていない別人物の同系統の採用済み参考を使う。試作では独立参考の部品損失が現行候補より10％以上低下し（現行の損失が0なら改善判定を保留）、D5 の墨の距離と舞台サイズでの見分けやすさが悪化せず、owner が見た目を承認した候補を次の評価へ送る。独立参考がなければ採否を保留する。製品の閾値は D8 に従って本評価前に固定する。
- **形と再現性**: 校正用の独自の幾何で座標変換、前後関係、可視区間、欠測、重み、パーツの対応違いを検査する。実データでは出力を再生成し、共有部品の SVG が3表情で一致すること、各表情の差分を検査する。製品描画へ反映する候補は全8表情で validate を通し、舞台サイズの SVG と pnpm measure --check の結果を比較する。ツールと実行条件の記録は D5 に従う。
- **判断**: 参考に近いか、同じ人物に見えるか、表情が読めるかは owner が確認する。改善がなければ、必要な区間を測れているか、モデルに必要な形があるかを分けて記録する。

## 代替案と影響

- **直接トレースしたSVGを各表情に使う**。各画像の見た目に早く近づく。表情を増やすにはパーツの整理や位置合わせが別途必要で、D6 上は非公開の比較用となる。
- **既存のランドマークと全体の墨の距離だけを使う**。注釈の手間が少ない。巻き髪や上まぶたで、どの対応がずれているかを特定しにくい。
- **部品をラベル付けして当てはめる方式**。注釈と候補の設計に時間がかかる。最初は採用済み参考の主な房に範囲を絞り、区間を追加するごとに注釈時間と改善した差を記録する。髪以外へ広げる判断は試作の結果を見て行う。

## 承認後の順序

1. R1 の生成記録、R2 の owner 採否と非公開の置き場を確認する。条件に合う採用済み参考がなければ画像を使う試作は保留し、独自の校正図だけで計測と合成を検査する。
2. R4 相当の独立読みと校正で、追加アンカー、可視区間、房の対応の誤差を確認する。既存の段 a と段 b を比較に使う場合は Issue #10 の評価モード（snap / hair）、R5 のランドマーク当てはめ、R6 の墨距離評価の利用可否を確認する。
3. 非出荷の描画候補に房 ID、曲線、可視区間を返す試作インターフェースを作り、注釈と対応を固定して中立の当てはめを行う。続けて共有形状を使う表情比較と独立参考での評価を行う。
4. owner の見た目の確認を経て、製品に適用する場合は既存の R6〜R9 の実装計画への組み込みを別タスクの仕様にする。
