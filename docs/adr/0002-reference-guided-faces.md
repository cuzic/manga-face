# ADR 0002: 参考画像に当てはめて顔を作る — 生成した参考、PD / CC0 の参考、ランドマークの当てはめ、出荷の規則

- 状態: **一部実装済み(R0、R1 の生成ツール、R2 の参考の採否と来歴検査、R3 の前処理とベクター化)**。R1 の初回生成は owner の承認を得て実施し、ai-0001・ai-0002 を採用した。R4 は AI 計測に切り替えた(Q8)。
- 日付: 2026-11-23
- 関連: ADR 0001(顔のモデル。**この ADR は D6 を改訂する**)、svg-diagram の ADR 0079 / 0080
- 範囲外: 3/4 の顔、全身、色の再現(参考は線と形の当てはめにだけ使う)、ニューラルネットワークの学習
- 例のデータはすべてこの ADR のための作り話。参考の画像は、実在の作品名・キャラクター名・作家名を含む指示で作らない

## 背景

ADR 0001 のモデルは、ゼロから設計した数(輪郭・目・眉・口・髪)で顔を描く。スパイクの見た目の評価は「汎用的で、子どもっぽく、髪がおかっぱに近い」で、**数値の目標(目の大きさ、顔の縦横比、髪の外形)を、何に合わせるか**を持っていなかった。

owner が決めた方向(2026-11-23):

- **ゼロから設計せず、参考の画像から始め、私たちのパラメトリックなモデルを当てはめる**(analysis by synthesis)。
- **参考は OpenAI の画像 API で作る**(線画の、マンガ風の顔のシート。同じ人物の表情、正面、白地。**低い解像度・最も安い設定だけを使う**。D1)。指示は一般的な語だけで、作品名・キャラクター名・作家名を使わない。人が 1 枚ずつ確認し、知られたキャラクターに似たものを捨てる。
- **生成した画像は参考にだけ使う**(当てはめと評価)。**出荷する絵にはしない**。出荷する絵は、常に、パラメータから私たちのコードが描き直したもの。
- **参考は非公開の置き場に置く**(公開リポジトリに置かない)。公開リポジトリには、出所の記録と、当てはめたパラメータだけを入れる。
- 1 枚ごとに、モデル・日付・指示・画像のハッシュ・確認の結果・使ったかを記録する。
- **PD / CC0 の絵**(国立国会図書館の `pdm`、OpenGameArt の CC0 の肖像を 1 点ずつライセンスを確かめて、Wikimedia の PD-old)も、出所の記録つきで、参考にも、トレースにも使ってよい。著作権のある絵と、出所の不明なスクレイプのデータセットは使わない。

この ADR はその設計(生成、確認、整理とベクター化、部品の分け方、2 段の当てはめ、結果の使い方、権利の線、道具の置き場、品質の指標)を決める。

| ランドマークの当てはめ(顔の位置合わせ)、Chernoff の顔 | 段 a。ランドマークは少数の点で、最小二乗が閉じた形で解ける |

## スパイク(`tools/fit/`、`refs/pd/`。API は呼んでいない。レビュー 1 回目のあとで作り直した)

**この節の数値の出どころ(分割前のコード)**: 数値は、**U1 の分割(PR #9)より前の `src/face.ts`**(+ 内部の関数の `export` と `hair: false` の選択肢を足した試しの版)で出した。その `src/` の変更は、#9 と衝突するので、この PR から**取り除いた**(revert のコミット)。そのため **`tools/fit/landmarks.ts` と `render.ts` は、このブランチでは動かない**(内部の関数と `hair` の選択肢が無い。ファイルの先頭に `@ts-nocheck` と理由を書いた)。**コミットした出力(`docs/adr/0002-spike-*`)は、分割前のコードで走らせた記録として残す**。**依存の Issue #10(`hair: false` と `snap: false`)が入ったあとの commit で、スパイクを 1 回やり直し、そのとき使った commit を記録する**(R5 の前提。`tools/fit/landmarks.ts` は、#9 の内部のモジュール(`geometry.ts` など)から直接 import する。D7)。

**参考を替えた**: 最初のスパイクの参考(Open Clip Art の「Manga Boy」)は、Wikimedia Commons の説明が「作者本人を描いたアニメ風の画像」と書いており、**実在の人物を描いたもの**だった。CC0 は著作権を解くが、人物の権利は解かない(D6 の 1)。**リポジトリから外した**(PR の最初のコミットの履歴には残る。画像は CC0 で権利の問題はないが、実在の人物の絵なので、以後使わない)。

**新しい参考**: Wikimedia Commons `File:Surprising face of manga 2022-08-30.png`(Asanagi 作、「own work」としてアップロード、848×848、**CC0**。ページの API のメタデータとウィキテキスト(`{{self|cc-zero}}`)を 2026-11-23 に読んで確認。SHA-1 `3bebdda5…`)。**手描きの線画**の、驚いた表情の、一般的な顔(実在の人物ではなく、知られたキャラクターでもない)。紙の質感の背景つき。出所の記録は `refs/pd/commons-surprising-face-2022.provenance.json`。

- **階層: B(アップロード者が CC0 に捧げたもの。PD-old ではない)**。D6 の 5 の「アップロード者が作者らしいか」の確認: アップロード者は 2010 年から Commons に貢献(編集 約 5,400 回)で、写真と手描きの絵を「own work」として上げている。ページに別の作者を示すものはない。**逆画像検索はこの環境ではできなかった。「らしい」であって、証明ではない**。人の確認(owner)が済むまで、この ADR のスパイクを超える用途(髪の出荷を含む)には使わない。
- **弱点**: 表情が 1 つ(驚き。モデルの `surprise` のプリセットで当てはめる)、頭身がマンガのデフォルメ(丸く幅広い顔、近い大きな目、幅広い口)で、モデルの `young` の既定値とも `mature` とも離れている、鼻が無い、耳が大きなこぶ(モデルの耳でない)。**だから、この参考は「当てはめの道具が動くこと」と「モデルに足りない所」を見せるもので、一般的な数値を出すものではない**。

**読み取れること(最初のスパイクの結論を、実際に描かれる値で書き直した)**:

- **モデルは、この参考を、ノイズの範囲(σ の数倍)では当てはめられない**。残差は σ の 24 倍で、4 個の描かれる値が範囲の端に張り付く。**この参考の顔は、モデルの範囲より、目が小さく(`eyes.h` 下限)、高く(`eyes.y` 下限)、近く(`eyes.gap` 下限)、あごが深い(`head.chin` 上限)。つまり、モデルの範囲が、このデフォルメの頭身に届かない**。範囲を決める根拠を持たなかったことを、当てはめが示した。
- **口がいちばん合わない**(残差 98〜122 px = モデルの座標で 31〜39)。原因は 1 つ: **この参考の口は顔の幅の約 65% の広い逆台形で、`surprise` のプリセットの口(`o`、幅 ×0.7)と形が違う**。1 回目に書いた「口が広い」は、`normalize` で幅が 34 に押さえられていたのを、要求した値(47)で報告した**見かけ**だった。今回は、描かれる値(47)で、それでも合わない、と読む。**モデルに、広く開く口の形が無い**ことが足りない所。
- **眉(左 59 px、右 36 px)と頬(59 px)も大きい**: 参考の眉は、外側が下がる長い曲線で、モデルの眉は短い。頬は、モデルの輪郭が、参考の丸く張った頬(顔の幅が高さに近い)に届かない。
- **目の形も違う**: 参考の目は、細い線の楕円で、瞳が小さな点。モデルは、太い上まぶたと大きな虹彩。目の位置と大きさは合っても、形の差は段 b(見た目の当てはめ)の対象。
- **注意: 基本のパラメータを「驚き」の顔から当てた**。D5 の(1)は「基本は**中立**の顔から」と決めているが、このスパイクの参考は驚きの 1 表情だけで、プリセット(`surprise`: `hMul` 1.25、`iris` 0.62 など)を固定して基本を当てた。**したがって「目が小さい・高い・近い」の読みは、`surprise` の差分と絡んでおり、基本の目の性質とは言えない**(驚きの目は、開く方向の差分を持つので、基本の `eyes.h` が下限に張り付くのは、差分の掛け方の影響を含みうる)。**この 3 つの読みは「この当てはめで、範囲の端が見えた」までの意味で、モデルの範囲の結論には使わない**。範囲の根拠にするのは、`in` の参考(D8)の中立の顔から当てた値だけ。
- **頭頂(髪の高さ)は当てはめから外した**: 髪の高さは顔の比率と別で、髪の当てはめ(D6 の 3)の仕事。1 回目は頭頂を含めたため、「目が高い」という結論が、髪の量に引きずられていた(頭頂を外すと、`eyes.y` の結論が動く)。
- **信用度**: 参考 1 枚、表情 1 つ、言語モデルによる読取り 2 回。数値の一般性は主張しない。**示したのは、(1) 道具の流れが決定的に動く、(2) 報告が「描かれる値」である、(3) 残差が「足りない所」を名指しする、の 3 点**。

## 決定

### D1. 生成: OpenAI の画像 API で、表情のシート(1 枚 4 表情)を作る。解像度は低く、設定は最も安いものに固定

- **モデル**: OpenAI の **GPT-Image-2.6** を使う(owner 決定、2026-11-23)。R1 は 1 枚の構図と人物の一貫性を重視し、[Sunburst](https://developers.openai.com/api/docs/models/gpt-image-2.6-sunburst)(`gpt-image-2.6-sunburst`)を使い、**`PROVENANCE` に版の名前を記録する**(版が変わると出力が変わるため、記録が再現の鍵)。
- **設定は最も安いものに固定する(owner の決定 2026-11-23: 「必ず、解像度を低くして安価な画像を作成する」)**: **サイズは、選んだモデルが対応する最小のもの**([GPT-Image-2.6 の公式ガイド](https://developers.openai.com/api/docs/guides/image-generation#size-and-quality)の寸法条件から、正方形の 2×2 シートは 816×816 が最小。各マスは 408×408。選んだモデルの実装時にも確かめる)、**品質は最も低い段(`quality: "low"`)**。**低い解像度で足りる理由**: 画像は当てはめの参考にだけ使い、出荷しない。当てはめに要るのは、目・口・輪郭の位置と、墨の大まかな形だけ(下の「当てはめへの影響」)。
  - **道具が強制する**: `generate.py` は、サイズと品質を**定数**として持ち、**それ以外を拒む**(コマンドラインの引数にも、環境変数にも、設定ファイルにも、上書きの手段を作らない。変えるには、ADR の改訂と、ソースの変更の PR が要る)。`--yes` の確認と、**1 回の実行あたりの枚数の上限(ソースの定数。初期値 20)**を持つ。**呼ぶ前に、予定の枚数 × 1 枚の費用の見積りを表示する**(価格表はソースに日付つきで持ち、表に無いモデル・サイズ・品質は拒む)。
- **シート**: 1 枚に同じ人物の **4 表情**を **2 列 × 2 行**で(816×816 では 1 マス 408×408)、正面、肩までの上半身、白い無地の背景、**一定の太さの黒い線画**(塗りなし、影なし、スクリーントーンなし)、文字なし。背景は不透明な白(透明は使わない)。1 回の呼び出しで 1 枚(`n = 1`)。**8 表情は 2 枚に分ける**: シート A = `neutral smile surprise angry`、シート B = `neutral laugh worry sad`(**どちらも中立を入れる**。D5 は基本を中立から当て、表情の差分はそのシートの中立に対する差分にするので、**2 枚のシートで同じ人物が保たれなくてよい**)。ADR 0074 の `think` は v1 のシートに入れない(ADR 0001 U4 の追加の表情と一緒に、あとで足す)。1 マスが小さすぎる(顔が 200 px 幅を切る)と R1 の試験で分かれば、4 列 × 2 行(1 マス 256×512)は選ばず、1 枚 1 表情に変える。
- **指示の雛形**(一般的な語だけ。変える所を `{…}` で書く。**作品名・キャラクター名・作家名・「○○風」を書かない**):

  > A character model sheet of one original fictional character, drawn as clean black line art on a pure white background, in a generic Japanese manga style. The sheet is a grid of 2 columns by 2 rows, each cell showing the same character's head and shoulders, front view, with a different facial expression: {expressions}. Same face, hair and clothes in every cell. {age}, {hair}, {eyes}. Uniform line weight, no shading, no colour, no screentone, no text, no labels, no borders between cells.

  変える所: `{age}`(teenager / young adult / adult)、`{hair}`(short / bob / long straight / curly short / ponytail など)、`{eyes}`(large round / medium / small narrow など)。`{expressions}` は 2 つの固定の列(シート A: neutral, smile, surprise, angry。シート B: neutral, laugh, worry, sad)のどちらか。**表情の順序と文言は固定**(同じ語で出す)。`{age}` は、**生成した参考の既定の `domain`**を決める(D2 の 3)。
- **規模と費用**: v1 は **40 人(= 80 枚のシート = 約 280 の顔)**を目標にする。採用率を半分と見て、生成は約 160 枚。**費用**: [公式料金表](https://developers.openai.com/api/docs/pricing)を 2026-11-23 に確認。GPT-Image-2.6 の画像出力は通常 $30 / 100 万トークン、Batch は $15 / 100 万トークン。比較用に、公式計算ツールの GPT-Image-2.6 共通表示では、1024×1024・`low` の出力は 823 トークン。Batch 料金に換算すると 1 枚約 $0.01235、同じサイズを 20 枚生成した場合は約 $0.25(画像出力のみ。プロンプトの入力料金は別)。初回の 816×816・`low` は同じ計算ツールで 718 出力トークン、Batch で 1 枚 $0.01077、20 枚 $0.2154(画像出力のみ)。試行は結果をすぐ確認できる通常の Image API で 1 枚ずつ行い、設定と確認手順が固まった後の一括生成に Batch を使う(owner 決定)。通常の Image API での 1 枚の生成は R1 の追加作業として `generate.py` に入れ、Batch と同じ定数・枚数上限・費用確認を強制する。それまでの 1 枚の試行(ai-0001 の元シート)は一時スクリプトで行い、要求の全体を来歴に記録した。R1 で採用モデル・最小サイズ・`low` の 1 枚あたりの費用を[公式計算ツール](https://developers.openai.com/api/docs/guides/image-generation#calculating-costs)で確認し、URL と日を `generate.py` の価格表と ADR に記録する。生成の前に、予定の枚数 × 1 枚の費用を表示し、確認(`--yes`)を要する。**線画の格子で、同じ人物が複数の表情にわたって保たれるのは、いまの画像モデルには難しい**(1 枚 4 表情に減らしたので、8 表情よりは易しい)。採用率は 50% を大きく下回ると見る(D8 の指標に採用率を入れ、Q3 の試験で測る)。
- **当てはめへの影響(低い解像度)**: (1) **顔の幅は約 300 px(スパイクの参考は約 500 px)**。画素の量子化の床(約 1 px)と読みの誤差が、顔の幅に対して約 1.7 倍の割合になる(**σ は、顔の幅に対する割合で報告し、R4 で低解像度の画像について測り直す**。D4)。(2) **D8 の門は σ の倍数のままにする**(σ が大きくなれば、モデルの単位での許容も広がる)。**ただし、モデルの単位(頭の円の半径 = 100)の絶対値も併記し、σ が顔の幅の 1.5% を超えるときは、門を機械的に広げず、owner が決める**(解像度のせいで門が甘くなるのを防ぐ)。(3) **墨のマスクの損失**は、参考の解像度のままで、モデルを同じ解像度にラスタライズして比べる(1 モデル単位 ≈ 1.5 px)。線が細い所はアンチエイリアスで薄くなるので、**2 値化のしきい値は参考ごとに決めて記録する**(D3)。potrace の曲線は粗くなるが、髪のシルエットと墨のマスクにだけ使うので足りる。(4) **目の瞳・まつげなどの細かい部分**は、この解像度では読めないことがある(段 b の目の形の当てはめは、読めた部分だけを対象にする。読めない点は「無し」(重み 0))。
- **API キーの扱い**: 環境変数 `OPENAI_API_KEY` からだけ読む。ローカルの gitignore 対象の `.env` を使う場合は、利用者が起動前に環境変数として読み込む。生成ツールは `.env` を直接読まない。**コマンドラインの引数・ファイル・設定に書かない。コミットしない。ログ・記録に出さない**。**環境変数が無ければ、スクリプトは何もせずに終了コード 2 で止まる**。CI には渡さない(生成は手元だけ。CI で走るテストは、API を呼ばない模擬で行う)。出力の置き場は、`.gitignore` された `refs/ai/`(手元の作業用。**公開リポジトリに入らない**)。
- **指示の衛生**: `{age}` `{hair}` `{eyes}` は、`generate.py` の中の**閉じた語彙**(上の例の語)からだけ選ぶ。**自由な文は入れられない**(テストで確かめる)。「Japanese manga style」は、作品名でも作家名でもなく**ジャンルの名前**で、「「○○風」を書かない」(作品・作家・キャラクターに似せる指示を書かない)に反しない、と明記する。
- **画像に付く来歴の情報**: API が画像に埋め込む C2PA などの来歴のメタデータは、**非公開の記録に保存する。無いときは、「無かった」と記録する**(「この日に生成した」の裏付けになる)。
- **再現と変種**: シードは指定できないので、**1 枚の記録が再現の根拠**(モデルの版、指示の全文、設定)。同じ人物の別の角度や表情が欲しいときは、編集 API を追加する場合は前のシートを渡し、親の画像のハッシュを記録する。編集にも生成と同じ最小サイズ・品質 `low`・枚数上限・費用確認を強制する。指定を保証できない編集経路は無効にする。

### D2. 人の確認と、記録の形式

**確認は、AI が生成した画像にも、PD / CC0 の参考にも、すべてに行う**(D6 の 1)。

1. 生成した画像は `refs/ai/pending/` に入り、**人が 1 枚ずつ見て**、`accepted` / `discarded` にする(**owner が最終の判断**。Claude が下見の一覧表を作ってよいが、**似ているか・実在の人物かの判断は人**)。PD / CC0 の参考も、使う前に、同じ確認を受ける。
2. **捨てる基準**:
   - **`resembles`(似ている)**: 知られた作品・キャラクター・作家の絵に似ている(髪型・目の描き方・服・小物の組み合わせで「あれだ」と思うもの)。**疑わしければ捨てる**。
   - **`depicts-real-person`(実在の人物を描いている)**: 実在の人物の肖像・似顔絵・自画像(出所の説明に「○○本人」「モデル」「自画像」などがあるものを含む)。PD / CC0 の絵が、実在の人物を描いていても、**使わない**(著作権と別に、人物の権利があるため)。
   - **`quality`(品質)**: **生成したシート**の基準と、**PD / CC0 の参考**の基準を分ける。
     - 生成したシート: 同じシート内の 4 マスで人物の同一性が保たれていない、表情が読めない、手や小物が壊れている、文字・ロゴ・署名が入っている、線が二重・太さが一定でない、格子が崩れている、背景が白でない。
     - PD / CC0 の参考: **白い背景・二重の線・格子は文字どおりには求めない**(紙の質感の背景や灰色の網目の影のある絵でも、しきい値で墨が取れればよい)。判断は「**当てはめに使えるだけの、きれいな墨が、2 値化のあとに取れるか**」(線が切れていない、顔の部品が読める、文字・ロゴ・署名が顔にかぶらない)。使う前に、しきい値と、取った墨の見た目を記録する。
   - **`out-of-scope`(範囲外)**: 正面でない、全身、複数人。
3. **`domain`(どの方向の様式か)を、確認のときに owner が付ける**(捨てるかどうかとは別。受け入れた参考にだけ付く)。**値は `young` / `mature` / `out`**(ADR 0001 の方向。**方向ごとに判定する**。owner の決定 Q11)。基準: 参考の頭身・様式が、その方向の範囲に入るか。
   - **`out` の理由は閉じた一覧**(記録の `out_reason`): `gag-chibi`(ギャグ・ちびのデフォルメ。このスパイクの参考)、`realistic`(写実)、`non-manga`(マンガの様式でない)、`other-direction`(`young` でも `mature` でもない年齢・様式。幼児・高齢など)、`other`(自由な文が必須)。
   - **生成したシートの既定は、指示の `{age}` が決める方向**(teenager・young adult → `young`、adult → `mature`)。**`out` は、既定から外す例外として、理由つきで付ける**(owner が画像を見たあとの `in` の偏りを防ぐ)。
   - **当てはめの前に付ける**。D8 の門は、方向ごとに、その方向の参考にだけ適用する。
4. **評価単位**: 画像の来歴と人物の同一性はシート単位、計測と表情の採否はマス単位。権利・類似・同一性に問題があるシートは全マスを捨てる。個別の表情だけ品質が悪ければ、そのマスに不採用理由を付ける。中立を捨てたシートは差分・分布・品質評価に使わない。方向ごとの「10 件」は採用済みの独立した中立シートを数え、同じ人物と判明したシートや編集の親子は 1 グループとして数える。差分は各表情について別途、採用マスの件数を報告する。
5. **記録(1 シート = 1 つの JSON)**: `id`(連番)、`kind`(`ai-generated` / `pd-cc0`)、`model`(版の名前)、`date`、`request`(**API に送った要求の全体**(指示の全文・設定・編集のときの親の画像のハッシュ))、`provenance_metadata`(API が付けた C2PA などの内容。**無いときは `none`**)、`sha256`(画像)、`review`(`accepted` / `discarded`)、`reason`(上の名前)、`domain`(`young` / `mature` / `out`。`out` のときは `out_reason`。後から変えるときは `domain_change`: 日・変えた人・理由)、`reviewer`、`cells`(位置・表情・採否・不採用理由・適用した輝度しきい値 `ink_threshold`、整数 0〜255)、`used_for`(`fit` / `eval` / `none`)、`derived`(当てはめの結果の id)。PD / CC0 の参考には、さらに `tier`(`A: PD-old` / `B: uploader-dedicated CC0`)、`source_url`・`author`・`licence`・`licence_checked`(日と方法)、`uploader_is_author_check`(B のとき。D6 の 5)、`depicts_real_person`、`resembles_known_character` を書く(`refs/pd/*.provenance.json` の形)。**非公開の置き場には画像と記録を、公開の `PROVENANCE.md` には記録の行(ハッシュ・結果・使った所。画像と要求の全文は置かない…ただし指示の雛形は ADR に公開済み)を入れる**。
6. 部品から導いたもの(当てはめた値、ベクター化した曲線)の記録は、**元の参考の id を持つ**(部品ごとの出所の記録)。**AI の参考ごとの当てはめの結果(`fit.json`)は、非公開の置き場に置く**(D6 の 1、D9)。
7. **record に、キーが入らないこと**を、`generate.py` のテストで確かめる(記録を書くのは同じスクリプト)。

### D3. 整理とベクター化

- **整理**: 傾きと余白をそろえ、2 値化(輝度のしきい値)し、小さな点を除く。シートは 2 × 2 の 4 マスに分ける(マスの位置は固定の格子。ずれたら人が直す)。**生成された線画の線が二重・途切れのときの整理**(Simo-Serra の単純化など)は、v1 では使わない(その参考は捨てる)。
- **v1 の道具**: **potrace**(アルゴリズム。Python の `potracer` か、`potrace` の実行ファイル)で、暗い層の輪郭を少ないベジェに直す。マンガ風の顔は、太い線と塗りなので、輪郭のトレースで足りる(スパイク: 12.5 KB、352 区間)。細い 1 本の線(鼻、口)が二重の輪郭になる所は、段 a のランドマークと段 b の評価には問題ない。
- **中心線のベクター化**(Favreau 2016 / Noris 2013 / Bao と Fu 2023 / Deep Sketch Vectorization 2024)は、**v2 の選択肢**。1 本の線として、線の太さと位置を別に扱いたくなったとき(眉・まつげの太さの分布を取るときなど)に調査する。色の当てはめ(DiffVG / LIVE)は、v1 の範囲外。
- **線画への注意**(スパイク): potrace は塗りの形を輪郭にするので、線 1 本が**輪郭 1 つ(両縁)**になり、紙のざらつきも拾う(68 本、1,955 区間)。そこで、**線画の参考では、ベクター化の結果を、髪のシルエットと、距離の測りの墨のマスクに使い、中心線としては使わない**。R3 のテストは、色つきの絵と線画の PD の 2 点で行う。
- ベクター化の結果も**参考の一部**で、記録に元の id を持つ(出荷の規則は D6)。

### D4. 部品の分け方と、ランドマークの操作的な定義

- **v1: 画像を読む AI が計測する 19 点のランドマーク**。**定義は、モデル側(`tools/fit/landmarks.ts`)と参考側で同じ操作にする**(定義の食い違いが、当てはめの残差に混ざらないように):
  - `chin`: あごの輪郭の最も低い点。
  - `cheekL/R`: 顔の輪郭の x。高さは、`目の線 + 0.2 ×(あご − 目の線)`(目の線は、左右の目の中心の y の平均)。
  - `earL/R`: 耳の最も外側の点(耳の中心の高さ)。
  - `eyeX_outer` / `eyeX_inner`: 目の輪郭の、顔の中心から遠い側 / 近い側の端(目の中心の高さ。まつげの跳ねは含まない)。`eyeX_top` / `eyeX_bottom`: 目のインクの最も高い / 低い点。
  - `browL/R`: 眉の線の外接矩形の中心。**弱い定義**(長く曲がった眉では、外接矩形の中心が推論ごとに揺れる。スパイクで σ が 7.5 px と大きかった。R4 で、「眉の墨の重心」か「眉の内側の端と外側の端の 2 点」への変更を試す)。
  - `noseTip`: 鼻の印の先。
  - `mouthL/R`: 口の輪郭の左端 / 右端の x(口の外接矩形の縦の中心の高さ)。`mouthC`: 口の輪郭の外接矩形の中心。
  - **頭頂は無い**(髪の高さは髪のもの)。参考に描かれていない点は「無し」と記録し、重み 0 にする。
- **計測**: 出典と利用条件を確認した画像入力対応モデルに D4 の定義と元のマス画像を渡す。中立は 19 点、他の表情は目・眉・口の 13 点。隠れている点や区別できない点は理由つきの欠測とし、座標を補完しない。出力はマス内の整数座標。範囲・点名・必須項目を検証し、モデル版・指示の版・推論 ID・マス原点・画像と来歴の SHA-256 を記録する。生成参考と結果は非公開で扱う。
- **再現性**: 同じ 5 枚に対して同じモデル版・指示・画像で独立した推論を 2 回行い、後の推論には前回の結果を渡さない。D8 の式で σ と両回の検出件数を点ごとに出す。人による入力や 1 週間の間隔は不要。
- **精度**: SVG の幾何から正解座標が得られる校正画像で、検出率と座標誤差を点別に検証する。校正画像には縮尺や位置が既知の変換、隠れて見えない点、複数の表情を含める。実画像では元画像とズーム画像から独立に読んだ座標を元のマスに戻して照合し、検出の安定性を確認する。精度・欠測の基準は本評価前に固定し、基準を満たさない点を当てはめに使わない。
- D2 の画像の採否・権利確認は owner が行う。学習データや利用条件が確認できない専用モデルの採用は保留する。
- 部品ごとの切り出し(目・口の画像)は、ランドマークから作る。髪は、ランドマークの外側の暗い層のシルエット(ベクター化の結果)。

### D5. 当てはめは 2 段

**当てはめるのは、モデルが実際に描く値**(`normalize` と依存する制約(ADR 0001 D2)を通したもの)。**報告するのも、その値**。要求した値と描かれる値が違うものは、`clamped_by` に書く(スパイクで、要求した値と描かれる値が違って、結論が間違った)。当てはめの結果が `validate`(全表情)を通らない人物は、**拒む**(段 a は 1 つの表情だけ当てるので、ほかの表情で眉が目に入るなどが起きうる)。

- **段 a: ランドマークの最小二乗**(決定的)。比と位置(あごの深さ、頬の幅、目の位置・幅・高さ・間隔、口の位置と幅、眉の高さ)を当てる。未知数は、画像 → モデルの写像(拡大率と平行移動。**与えられたパラメータでは、閉じた形の相似変換**)と、モデルのパラメータ。モデルが刻みに丸めるので勾配が無く、**刻みの格子上の座標降下**(厳密に改善するときだけ動く。決定的)。ランドマークの重みは一様(ノイズ σ で重みを付けると、モデルの食い違いが σ の数十倍のときに、問題が悪条件になる)。**σ は、残差を σ の倍数で報告し、D8 の門を決める単位に使う**。**頭頂は含めない**。出力: 描かれるパラメータ・`clamped_by`・`at_bound`・写像・ランドマークごとの残差(px とモデルの単位と σ の倍数)。
- **段 b: 見た目の当てはめ**(目の形、髪の外形)。**連続のパラメータには CMA-ES、離散の選択には外側の列挙**:
  - **連続のパラメータ**(目の `w` `h` `tilt` `iris` `lidW`、髪の分け目・側面の長さ・量の偏りなど)は、**丸めない連続の値で評価する**(当てはめ用に、`normalize` の刻みの丸めを切る評価モード(`snap: false`)をモデルに足す。丸めは、最後の 1 回だけ。丸めた値で再評価して、報告する)。刻みで区分的に一定の評価では、CMA-ES は同点で止まるため。**この選択肢と `hair: false` は `src/` の変更なので、この ADR の PR には入れず、別の Issue(#10。`[codex]`。テストつき・golden 変更なし)で作る。R5 / R6 はその Issue の完了に依存する**。
  - **依存する制約は、当てはめの間は罰則にする**: `snap: false` でも、`normalize` の依存する制約(顔の幅による口・目の間隔の押さえなど)は値を押しつけ、制約が効く所で損失が平らになる(CMA-ES が止まる)。そこで、当てはめの間は、**要求した値と描かれる値の差**(#10 が返す `clampedBy` と、押しつけの前後の値)に**罰則**(損失に、差の二乗 × 係数)を足し、探索が制約の内側に戻るようにする。**報告は、最後に、描かれる値(丸めたもの)で行う**。
  - **評価は、常駐の 1 つの Node の処理で行う**(評価のたびに `node` を起こさない。標準入力で、人物の JSON の束を受け、ランドマークとモデルの墨のマスクを返す)。スパイクの段 a は、評価 1 回あたり約 145 ms(1 回ごとに `node` を起こす。69 回で約 10 秒)。**列挙は段ごとに絞る**: 目・口の種類は、当てはめている表情のプリセットのものに固定し(合う種類が無ければ「合う種類なし」の印を付けて、D8 のダッシュボードへ)、髪の離散の選択(毛束の数 1〜9 × テンプレート 2)は**髪を当てるときだけ**列挙する。**費用の見積り**: 顔の部品の段 b は、1 つの表情あたり、世代 150 × popsize 12 = 約 1,800 評価。常駐で 1 評価 約 10〜30 ms(ラスタライズを含む)と置くと、約 20〜60 秒。約 280 の顔で 1.5〜5 時間(顔の部品だけ)。髪の列挙(約 18 通り)を付けると約 18 倍の評価で、髪を当てる 1 つの表情あたり 6〜18 分。**R6 に、評価回数の上限(予算)を置き、超えたら止めて報告する**。
  - **ラスタライザの版を固定する**: マスクの損失は、固定の解像度でラスタライズした墨を使う。**既存の Playwright Chromium を使い、Playwright と Chromium のビルドを固定して記録**し、「同じ入力で同じ `fit.json`」の CI の検査は、**その固定の版でだけ**行う(版が違うと、縁の画素が違い、損失の下位の桁が変わる)。
  - **離散の選択**(毛束の数、髪のテンプレート、目・口の種類)は、**CMA-ES の外で列挙する**(各候補で、連続のパラメータを CMA-ES で当てて、最良を取る)。
  - **損失**: 線画の参考は、**墨のマスクまでの距離**(墨の中が 0)を両方向で、平均する(参考の墨 → モデルの墨、モデルの墨 → 参考の墨)。**縁までの距離にはしない**(線 1 本が両縁を持つので、正しく置かれたモデルの線が、縁から線の太さの半分だけ離れ、最小が線の上からずれる)。モデルの墨のマスクは、**固定の解像度でラスタライズ**したもの(固定した Chromium ビルド)。塗りの領域(髪)は、領域の縁どうしを比べる。
  - **測る領域**: 当てはめる部品を含む矩形(顔の部品は、耳と髪を外す。髪を当てるときは、髪を含む)。モデルは、当てはめない部品(髪など)を描かずに測る(`faceFragment` の `hair: false`)。
  - **写像**: 段 a の写像を固定する(段 b の間は動かさない)。
  - **ライブラリ・シード・停止**: pycma の `cma`(`requirements.txt` に固定して足す。バージョンを記録)、`seed = 1`、`popsize` 12、初期の `sigma0` = 範囲の幅の 0.15、停止は pycma の絶対許容値 `tolfun = 1e-3 × 初期損失` または 150 世代。R6 で cma と推移依存、Python・Node、コンテナのダイジェスト、CPU アーキテクチャと BLAS のスレッド数(1)を固定する。この環境内で、キー順と数値の丸めを固定した `fit.json` のバイト一致を CI で検査する。環境をまたぐ比較では R6 で規定する数値許容差を使う。
  - **DiffVG / LIVE は使わない**(モデルを微分可能に書き直す費用が大きい。色も v1 の範囲外)。
- **表情ごとのずれ(シートの当てはめ。1 枚 4 表情)**: プリセットは、人物の基本の目・眉・口に対する**差分**(ADR 0001 D3)。そこで、(1) **中立の顔から基本のパラメータを当てる**(段 a・b)。(2) **基本を固定して、各表情の差分のパラメータ**(数値は `src/presets.ts` の `Preset` 型を参照。たとえば目と口の `wMul`、目の `hMul`・`irisMul`、眉の `thickMul`。離散の種類は数値と別に選び、ランドマークやマスクで識別できない項目は固定する)**を、その表情のランドマークと墨のマスクに当てる**。(3) **シートをまたいで、差分を分布として集める**(R7)。スパイクは、表情 1 つ(驚き)を、プリセットを固定して基本だけ当てた。
- **丸め(刻み)と端**: 当てはめた値は、モデルの刻みに丸めたもの。範囲の端に張り付いた印を付けて出力する(スパイク: 描かれる値で 4/9)。

### D6. 当てはめの結果の使い方と、出荷の規則(ADR 0001 D6 の改訂)

**ADR 0001 D6 の改訂**: 生成モデルの出力は、「出荷する絵」としては引き続き許さない。**「当てはめの参考」としては、この ADR の規則の下で許す(この ADR が受理されてから)**。ADR 0001 の D6 の本文に、この条件つきの注を足した(同じ PR)。

1. **すべての参考(生成した画像も、PD / CC0 の絵も)に、D2 の確認を行う**: 似ていないか(`resembles`)、**実在の人物を描いていないか(`depicts-real-person`)**。CC0 / PD は著作権を解くが、**人物の権利と、既存のキャラクターへの類似は解かない**。OpenClipart や Commons の CC0 のような、アップロード者の宣言に基づく収集は、**既存のキャラクターのファンアートが CC0 を名乗って入ってくる道**にもなる。
2. **パラメータの範囲とプリセット**(当てはめた値の分布から作る): **出荷してよい**。数(比・位置・大きさ)は、特定の絵の形ではない。ただし、(a) **出荷する値は集合から集計する**。範囲の端には個別値の最小・最大を使わず、10・90 パーセンタイルを出発点に、パラメータごとに事前定義した刻みで丸め、モデル上の制約を満たす候補を選ぶ。既定値・差分・髪も丸めた集合統計を使う。PR では変更した定数を集計と突き合わせ、個別の数値列や曲線を転記していないことを確認する。(b) **公開する範囲・中央値は、その方向(`young` / `mature`)の独立した推定用の参考 10 件以上から、方向ごとに作る**(`out` は入れない。少ないと 1 枚の値を読み戻せる)。**ある方向が 10 件に届かなければ、その方向の範囲・プリセットは変えない**(止める側に倒す)。(c) **AI の参考ごとの当てはめの結果(`fit.json`)は、非公開の置き場に置き、公開しない**。
3. **残差**(当てはめの足りない所): モデルの改良の入力にする。**参考の形をそのまま取り込まない**(足りない自由度を、私たちの言葉(パラメータ)で足す)。
4. **髪のテンプレート**(いちばん鋭い問題。髪の外形は、形そのものが絵)。**owner の決定(Q2、2026-11-23): 「ChatGPT の生成画像を元にする形で作り直そう」**:
   - **v1 の髪は、生成した参考(OpenAI の画像 API)に当てはめた「パラメータ」から、私たちのコードが描き直す**(外形の比、毛束の数、先の角度、量の偏り、分け目の位置の分布。D5 の段 b)。**トレースした曲線は、どの出どころのものも、v1 では出荷しない**。
   - **PD / CC0 のトレースは、v1 の髪には使わない**(PD / CC0 の参考は、当てはめの参考と、`tier` の記録つきの比較にだけ使える)。出荷の規則(整理の偏差・2 点以上の出どころ)は、将来、トレースの出荷を許すときの下限として、ADR 0002 の改訂で扱う。
   - **出荷しない: 生成した参考(AI)の曲線**。整理・単純化・平均化しても出荷しない(**これは変えない**)。パラメータの分布を通してだけ、髪のテンプレートに影響する。
   - **スパイクのやり直し**: いまの PD の参考のスパイクは、道具の動作を試すもの(R5 の回帰の検査)としてだけ残す。**髪を含む当てはめのスパイクは、生成した参考が最初に承認されたとき(R1 の最初の実行のあと)に、生成した参考でやり直す**。
5. **使ってよい PD / CC0 の出どころと、確かさの順**: **階層 A: 本物の PD-old**(没後の期間が過ぎた、国立国会図書館の `pdm` の資料、Wikimedia の PD-old)。**階層 B: アップロード者が CC0 に捧げたもの**(OpenGameArt の CC0、Wikimedia Commons の CC0)。**B は、第 2 の確認を要する**: アップロード者が作者らしいか(同じ名前が元のサイトにあるか、ほかの作品、既知のキャラクターでないか)を調べて、記録する(`uploader_is_author_check`)。**A を B より優先する**。**1 点ずつ**、ライセンスをページのメタデータとテンプレートで確かめる(`licence_checked` に方法を書く)。**著作権のある絵、出所の不明なスクレイプのデータセット、ライセンスを確かめていない絵は使わない**。
   - **NDL `pdm` の資料**: 著作権の保護期間が過ぎても、**著作者人格権(著作権法 60 条の趣旨)は残りうる**。輪郭のトレースは低リスクだが、**作品を歪める「整理」は、変形として記録し、著作者の作品として示さない**。
6. **記録のない参考は使わない**(`PROVENANCE.md` に行が無ければ、当てはめの入力に使えない。R2 のテスト)。
7. **出荷する絵は、常にパラメータから描き直したもの**(`faceFragment`)。参考の画像、ベクター化した曲線(出荷してよい場合を除く)、非公開の置き場の中身は、パッケージにも公開リポジトリにも入らない。

### D7. 道具の置き場

- **`tools/fit/`(Python)**。npm パッケージには入れない(`package.json` の `files` に含めない)。依存は `tools/fit/requirements.txt`(`numpy` `scipy` `pillow` `potracer`)。**モデルの数値は TypeScript(`src/`)が持ち、Python は `node tools/fit/*.ts` を呼んで取る**(式の二重化を避ける。**範囲(`RANGES`)・各方向の既定値(`DIRECTIONS`)・髪の既定も、Node の評価の処理が返し、`fit.py` は数値の写しを持たない**。スパイクの `fit.py` の `PARAMS` と `BASE` は写しなので、R5 で外す。スパイクの `landmarks.ts` / `render.ts`)。**`src/face.ts`(U1 の分割後は各モジュール)を `tools/fit/` にコピーしない**(モデルの二重化は、数値がずれる)。**`tools/fit/landmarks.ts` は、U1 の内部のモジュール(`../../src/geometry.ts` など、#9 の置き場)から、`faceSegs` `flatten` `faceHalfWidth` を直接 import する**。`tools/` は出荷しないので、公開の API(`src/index.ts` の再 export)は増えない。公開するのは、#10 の `hair` と `snap` の選択肢だけ。
- 出力は **JSON**(当てはめたパラメータ・残差・出所の id)。プリセットや範囲の更新は、人が見て PR にする(自動で `src/` を書き換えない)。
- 非公開の置き場(`cuzic/manga-face-refs`)は、**画像・記録・ランドマークの座標・ベクター化の曲線(AI の参考由来)**。公開リポジトリに入れるのは、記録の行(ハッシュ・結果)、PD / CC0 の参考とその派生、当てはめたパラメータ。

### D8. 品質の指標(ADR 0001 D7 に足す門)

**門の適用範囲(当てはめの前に決める)**:

- 参考は、確認のときに owner が **`young` / `mature` / `out`**(D2 の 3)を付ける。ギャグ・ちびの顔は `out`(いまのスパイクの参考)。
- **下の門(σ の倍数、範囲の端の張り付き、見た目の残差)は、方向(`young` / `mature`)ごとに、その方向の参考にだけ適用し、その方向が 10 枚以上そろってから判定する**(D9 の統計の下限と同じ)。**10 枚に届かない方向は判定せず、その方向の範囲・プリセットは出荷しない**(止める側に倒す)。**`out` の参考は、公開する範囲・中央値・プリセットに入れない**。
- **`out` の参考も当てはめ、残差は別の「モデルの限界の報告」に出す**。原因を 3 つに分ける: (a) **形の不足**(合う種類が無い。例: 広く開く口。新しい種類の候補)、(b) **範囲の狭さ**(連続の値が端に張り付く。範囲を広げるかを owner が決める)、(c) **ランドマークが不明**(参考に描かれない・定義が曖昧。例: 耳・鼻・眉)。
- **`young` / `mature` の参考が門に落ちたら、モデルの問題として扱う**(`out` に移さない)。`out` に変えるには、owner の判断と理由が要り、記録の `domain_change` に残す。
- **強制は道具が行う(R2)**: `fit.py` は、`domain` の無い記録を**拒む**。当てはめの結果(`fit.json`)と派生記録(`derived.json` の `derived`)に、**そのときの `domain` とレビュー済み来歴 JSON の SHA-256 を刻む**。来歴のバイト列は派生結果を書いたあとも保存し、同じ入力ハッシュで追跡できるようにする。R8 の報告は、`domain_change` の日が最初の当てはめより後の参考を**すべて列挙する**。**`out` の割合を、生成のまとまりごとに報告する**。
- **門は、手元で走らせ、公開の要約を作る**(AI の参考は非公開の置き場にあり、CI は見られない): R8 の道具が非公開の置き場に対して門を走らせ、**公開の要約**(方向ごとの枚数、残差の中央値と最大(σ の倍数)、端への張り付きの割合、`domain_change` の一覧、入力のハッシュの一覧)を書く。**CI は、その要約の閾値と、ハッシュが `PROVENANCE.md` の行と一致することを検査する**。
- R5 の再現の検査(回帰)は、いまの `out` の参考を使ってよい(それは道具を試すもので、門ではない)。


見分けやすさ(ADR 0001 の Q10)とブラインド確認に、**参考との距離**を足す。**目標は、測ったノイズ σ(D4)の倍数で決める**(ノイズの床の近くに置かない。最初の案の「RMS 中央値 ≤ 6」は、当時の読取り誤差に近く、門が計測の誤差に左右される)。**表の目標は初期値**。実装担当が R4 の測定と基準づくり用の参考を使い、計算式・集計単位・閾値を文書化して、本評価用の参考の結果を見る前に固定する。基準づくりと本評価は参考を分け、固定後の変更は ADR の改訂で扱う。owner は最後に見た目を承認する。解像度が低いと σ が顔の幅に対して大きくなるので、**モデルの単位の絶対値も併記する**。固定した閾値は、本評価の前に owner が承認する。σ が顔の幅の 1.5% を超えるときは、閾値を機械的に広げず owner が決める。舞台サイズでの表情の見分けやすさ（ADR 0001 D7）は採用の必須条件とし、その条件を満たす案の中で参考画像との距離を小さくする。

R4 の 2 回の読取りの差を `Δx, Δy` とし、ランドマークごとに両回で読めた画像について `σᵢ = max(2 px, sqrt(mean((Δx² + Δy²)/4)))` とする。異なる顔幅を混ぜるときは各読取り差と 2 px の床を顔幅で割った単位で集計し、評価画像の顔幅を掛けてその画像の画素単位に戻す。段 a の参考ごとの値は `sqrt(mean((rᵢ/σᵢ)²))`。ここで `rᵢ` は画素で測った点のユークリッド残差で、欠測は平均から除く。段 b の比較値は `100 × 墨までの平均距離 / 顔幅`、3σ の相当値は `100 × 3 × sqrt(mean(σᵢ²)) / 顔幅`。本評価前に、欠測で評価不能となる条件も固定する。

R7 は方向ごとに、画像の親子と同一人物をグループ化し、基準づくり・範囲推定用と本評価用に事前に分ける。推定用の独立した中立が 10 件に達してから、現行範囲より広い探索範囲で当てはめ、D6 の集計で公開範囲案を作る。探索でも幾何の制約を保つ。範囲案を固定して本評価用の参考を当てはめ直す。張り付きは方向と連続パラメータごとに、その値を評価できた独立した参考のうち、正規化後の描画値が上下いずれかの端から事前に固定した許容差以内にある件数の割合。基本は中立、差分は表情別に数え、各分母も報告する。本評価が 10 件に満たない項目は出荷判定を保留する。結果を見て候補を修正する場合は別の本評価用参考で判定し直す。

| 指標 | 内容 | 初期の目標 |
|---|---|---|
| 段 a の残差(方向ごと。`out` を除く) | 当てはめ後のランドマークの RMS(参考ごと)を σ の倍数で。ランドマークは**操作的に定義**(D4) | **中央値 ≤ 4σ、最大 ≤ 8σ**(スパイク: 24σ。**この参考は `out` なので門の対象ではなく、参考値**) |
| 範囲の端への張り付き(方向ごと) | **描かれる値**が範囲の端に張り付く割合(その方向の参考。`out` を除く) | **方向・パラメータごとに 20% 以下**(スパイク: 9 個中 4 個。範囲を広げる根拠) |
| 依存する制約の押しつけ | `clamped_by` になるパラメータの割合 | 報告する(押しつけが多いパラメータは、制約か範囲の見直し) |
| 見た目の残差(方向ごと) | 段 b の、墨のマスクまでの距離(顔の幅に対する %。両方向の平均) | **中央値 ≤ 3σ の相当**(σ の画素への換算で決める。スパイク: 3.7%、段 a だけ) |
| 部品ごとの残差 | 目・眉・口・輪郭・髪の部品別(ダッシュボード) | 上回る部品を、モデルの改良の優先にする |
| 生成の採用率 | 生成した画像のうち、D2 の確認を通った割合 | 報告する(**50% を大きく下回ると見る**。Q3 の試験で測る) |

出荷物(モデルの出力)が、**参考の分布の範囲に収まるか**も測る(範囲の外の人物を作れてしまうとき、範囲を絞るか広げる)。
