# ADR 0002: 参考画像に当てはめて顔を作る — 生成した参考、PD / CC0 の参考、ランドマークの当てはめ、出荷の規則

- 状態: 提案(Draft。2026-11-23。owner が方向を承認済み。**非公開の参考の置き場(`cuzic/manga-face-refs`)は、この ADR が受理されるまで作らない**。API は呼んでいない)
- 日付: 2026-11-23
- 関連: ADR 0001(顔のモデル。**この ADR は D6 を改訂する**)、svg-diagram の ADR 0079 / 0080
- 範囲外: 3/4 の顔、全身、色の再現(参考は線と形の当てはめにだけ使う)、ニューラルネットワークの学習
- 例のデータはすべてこの ADR のための作り話。参考の画像は、実在の作品名・キャラクター名・作家名を含む指示で作らない

## 背景

ADR 0001 のモデルは、ゼロから設計した数(輪郭・目・眉・口・髪)で顔を描く。スパイクの見た目の評価は「汎用的で、子どもっぽく、髪がおかっぱに近い」で、**数値の目標(目の大きさ、顔の縦横比、髪の外形)を、何に合わせるか**を持っていなかった。

owner が決めた方向(2026-11-23):

- **ゼロから設計せず、参考の画像から始め、私たちのパラメトリックなモデルを当てはめる**(analysis by synthesis)。
- **参考は OpenAI の画像 API で作る**(線画の、マンガ風の顔のシート。同じ人物の 8 表情、正面、白地)。指示は一般的な語だけで、作品名・キャラクター名・作家名を使わない。人が 1 枚ずつ確認し、知られたキャラクターに似たものを捨てる。
- **生成した画像は参考にだけ使う**(当てはめと評価)。**出荷する絵にはしない**。出荷する絵は、常に、パラメータから私たちのコードが描き直したもの。
- **参考は非公開の置き場に置く**(公開リポジトリに置かない)。公開リポジトリには、出所の記録と、当てはめたパラメータだけを入れる。
- 1 枚ごとに、モデル・日付・指示・画像のハッシュ・確認の結果・使ったかを記録する。
- **PD / CC0 の絵**(国立国会図書館の `pdm`、OpenGameArt の CC0 の肖像を 1 点ずつライセンスを確かめて、Wikimedia の PD-old)も、出所の記録つきで、参考にも、トレースにも使ってよい。著作権のある絵と、出所の不明なスクレイプのデータセットは使わない。

この ADR はその設計(生成、確認、整理とベクター化、部品の分け方、2 段の当てはめ、結果の使い方、権利の線、道具の置き場、品質の指標)を決める。

## 先行事例(その使い道)

| 事例 | 使い道 |
|---|---|
| ベクター化: potrace(Selinger 2003)、autotrace | **v1 の道具**。きれいな線画の輪郭(塗りの形)を、少ないベジェに直す。マンガ風の太い線・塗りの髪は、輪郭のトレースで足りる(スパイク) |
| 線画のベクター化の研究: Favreau ら 2016(忠実さと単純さの大域的な最適化)、Noris ら 2013(位相に基づく、きれいな線画のベクター化)、Bao と Fu 2023、Deep Sketch Vectorization 2024(暗黙の曲面の取り出し)と Simo-Serra の線画の単純化(2016。ラフ → きれいな線) | **中心線**(1 本の線)が要るときの選択肢。v1 では使わない。参考が生成された線画で、線が二重・途切れのときの整理の候補(R3 の調査で再確認する。**ここの文献の引用は、著者・年の記憶に基づく。実装前に原典で確かめる**) |
| 微分可能なベクター描画: DiffVG(Li ら 2020)、LIVE(Ma ら 2022。色つきの画像の階層的なベクター化) | 色の当てはめの選択肢。**v1 では使わない**(線と形だけを当てはめる)。モデルを微分可能に書き直す費用が大きい |
| 導関数なしの最適化: CMA-ES | **段 b の v1**。モデルの数は少ない(20 前後)。丸め(刻み)のある評価でも使える |
| ランドマークの当てはめ(顔の位置合わせ)、Chernoff の顔 | 段 a。ランドマークは少数の点で、最小二乗が閉じた形で解ける |
| ADR 0001 の先行事例(パーツ組み合わせ式、Parametric Caricature、VectorTalker、OmniSVG など) | OmniSVG は生成物の権利が不明確なので、引き続き出荷物には使わない |

## スパイク(`tools/fit/`、`refs/pd/`。API は呼んでいない)

**検証した参考 1 点**: Wikimedia Commons の `File:Manga Boy.png`(Astrid Graeber 作、Open Clip Art Library 25619 由来。720×800。**CC0 / PD-OpenClipart**。2026-11-23 に Commons のページのメタデータ(`LicenseShortName` CC0、`UsageTerms` Creative Commons Zero, Public Domain Dedication、テンプレート `{{PD-OpenClipart}}`)を読んで確認)。正面向きのマンガ風の顔。**線画ではなく、色つきのイラスト**(髪は黒の塗り)。SHA-1 `b42491da…`。リポジトリには、出所の記録つきで `refs/pd/` に置いた(PD / CC0 なので置いてよい。`*.provenance.json`)。

| 手順 | 結果 |
|---|---|
| ベクター化(`vectorize.py`。potrace のアルゴリズムの純 Python 版 `potracer` 0.0.4。暗い画素(輝度 < 80: 髪と線と瞳)と、シルエット) | 暗い層: 18 本の曲線、352 区間、SVG 12.5 KB。シルエット: 2 本、105 区間、3.8 KB。0.8 秒。髪の毛束の鋭い先、目と眉の輪郭が拾えている(`0002-spike-compare.png` の 2 枚目) |
| ランドマーク(20 点。`landmarks.json`) | **手で、50 px の格子を重ねた画像の上で打った**(誤差は ±5 px 程度。画像の幅の 1% 弱)。名前は `tools/fit/landmarks.ts` の `LANDMARK_NAMES`(あご・頬 2・耳 2・目 8・眉 2・鼻先・口 3・頭頂) |
| 段 a: ランドマークの最小二乗の当てはめ(`fit.py`) | 未知数は、画像 → モデルの写像(拡大率と平行移動。回転なし。与えられたパラメータでは閉じた形)と、モデルの 9 パラメータ(`head.cheek` `head.chin` `eyes.w/h/y/gap` `brows.dy` `mouth.w/y`)。モデルはパラメータを刻みに丸めるので勾配が無く、**刻みの格子上の座標降下**で解いた(決定的。63 回の評価、7.5 秒)。**ランドマークの残差(RMS)は、若い方向の既定値のとき 11.0 だったのが、当てはめ後 5.3**(単位はモデルの座標。頭の円の半径が 100 なので 5.3%)。最大は 11.5(左耳)。ランドマークごと: 目・眉・口・あごは 1〜6、**頬 8.6〜10.0 と耳 6.2〜11.5 が大きい** |
| 見た目の残差(段 b の指標の試し。顔の領域(y 400〜790、x 200〜580)のインクの縁の chamfer 距離) | 既定値 19.9 px → 当てはめ後 9.7 px(顔の幅 約 440 px の 2.2%) |
| 当てはめた値 | `head.cheek` 74、`head.chin` 98、`eyes.w` 25、`eyes.h` 13、`eyes.y` 14、`eyes.gap` 42、`brows.dy` 5、`mouth.w` 47、`mouth.y` 66(`0002-spike-fit.json`) |

**読み取れること(モデルに足りない所)**:

- **9 個のうち 5 個が、範囲の端に張り付いた**(`head.cheek` 74 = 下限、`head.chin` 98 = 上限、`eyes.h` 13 = 下限、`eyes.y` 14 = 下限、`mouth.w` は 47 で上限の 48 に近い)。この参考の顔は、いまの範囲より**細く、目が小さく高い所にあり、口が広い**。**範囲を決める根拠を持たなかったことを、当てはめが示した**。
- **頬と耳の残差が大きい**: 参考の頬は、頬骨から下へまっすぐ落ちる(いまの輪郭は頬骨で丸い)。あご先は尖りぎみ。輪郭の形の自由度(あごの角度と頬の張りを別にする。ADR 0001 の `chinW` と `jaw`)を当てはめの対象にしていない(まだ 9 個だけ)。
- **髪は当てはめていない**。参考の髪は、毛束の鋭い先と流れで、いまのテンプレートと形が違う(スパイクの図の 1・2 枚目と 4 枚目)。
- **弱点(この結果の信用度)**: 参考は 1 枚、ランドマークは私が目で打った、表情は中立だけ、色つきのイラストで線画ではない、当てはめは顔の部品の位置と大きさだけ。**数値の一般性は主張しない**。道具の流れが動くことと、残差が「足りない所」を指すことを示した。

## 決定

### D1. 生成: OpenAI の画像 API で、8 表情のシートを作る

- **モデル**: OpenAI の画像生成(gpt-image の系列)。**実装時に、そのときの最新の版を選び、`PROVENANCE` に版の名前を記録する**(版が変わると出力が変わるため、記録が再現の鍵)。
- **シート**: 1 枚に同じ人物の 8 表情(ADR 0074 の `neutral smile laugh surprise worry angry think sad`)を **4 列 × 2 行**で、正面、肩までの上半身、白い無地の背景、**一定の太さの黒い線画**(塗りなし、影なし、スクリーントーンなし)、文字なし。サイズは**横長 1536×1024**(4 列 × 2 行が 1 マス 384×512 程度に収まる)。品質は高。背景は不透明な白(透明は使わない)。1 回の呼び出しで 1 枚(`n = 1`)。
- **指示の雛形**(一般的な語だけ。変える所を `{…}` で書く。**作品名・キャラクター名・作家名・「○○風」を書かない**):

  > A character model sheet of one original fictional character, drawn as clean black line art on a pure white background, in a generic Japanese manga style. The sheet is a grid of 4 columns by 2 rows, each cell showing the same character's head and shoulders, front view, with a different facial expression: neutral, smile, laugh, surprise, worry, angry, thinking, sad. Same face, hair and clothes in every cell. {age}, {hair}, {eyes}. Uniform line weight, no shading, no colour, no screentone, no text, no labels, no borders between cells.

  変える所: `{age}`(teenager / young adult / adult)、`{hair}`(short / bob / long straight / curly short / ponytail など)、`{eyes}`(large round / medium / small narrow など)。**8 表情の順序と文言は固定**(同じ語で出す)。
- **規模と費用**: v1 は **40 枚(= 320 の顔)**。採用率を半分と見て、生成は約 80 枚。**画像 API の価格は変わるので、実装時にそのときの価格表で確かめる。ここでの見積り**(記憶に基づく目安): 1024 角で、品質が低 約 $0.01、中 約 $0.04、高 約 $0.17。**横長 1536×1024 の高品質は 1 枚あたり $0.25 前後**と置くと、80 枚で約 $20、再生成の余裕を 2 倍みても **$50 以内**。生成の前に、**予定の枚数 × 1 枚の費用を表示し、確認(`--yes`)を要する**。上限は owner が決める(Q3)。
- **API キーの扱い**: 環境変数 `OPENAI_API_KEY` からだけ読む。**コマンドラインの引数・ファイル・設定に書かない。コミットしない。ログ・記録に出さない**。**環境変数が無ければ、スクリプトは何もせずに終了コード 2 で止まる**。CI には渡さない(生成は手元だけ。CI で走るテストは、API を呼ばない模擬で行う)。出力の置き場は、`.gitignore` された `refs/ai/`(手元の作業用。**公開リポジトリに入らない**)。
- **再現と変種**: シードは指定できないので、**1 枚の記録が再現の根拠**(モデルの版、指示の全文、設定)。同じ人物の別の角度や表情が欲しいときは、画像の編集 API に前のシートを渡す(記録に親の画像のハッシュを書く)。

### D2. 人の確認と、記録の形式

1. 生成した画像は `refs/ai/pending/` に入り、**人が 1 枚ずつ見て**、`accepted` / `discarded` にする(**owner が最終の判断**。Claude が下見の一覧表を作ってよいが、**似ているかの判断は人**)。
2. **捨てる基準**:
   - **似ている**: 知られた作品・キャラクター・作家の絵に似ている(髪型・目の描き方・服・小物の組み合わせで「あれだ」と思うもの)。**疑わしければ捨てる**。
   - **品質**: 8 つの表情が同じ人物でない、表情が読めない、手や小物が壊れている、文字・ロゴ・署名が入っている、線が二重・太さが一定でない、格子が崩れている、背景が白でない。
   - **範囲外**: 正面でない、全身、複数人。
3. **記録(1 枚 = 1 つの JSON)**: `id`(連番)、`kind`(`ai-generated` / `pd-cc0`)、`model`(版の名前)、`date`、`prompt`(全文)、`settings`(サイズ・品質・`n`)、`parent`(編集のとき、親のハッシュ)、`sha256`(画像)、`review`(`accepted` / `discarded`)、`reason`(捨てた理由の名前: `resembles` / `quality` / `out-of-scope`)、`reviewer`、`used_for`(`fit` / `eval` / `none`)、`derived`(当てはめの結果の id)。**非公開の置き場には画像と記録を、公開の `PROVENANCE.md` には記録の行(ハッシュ・結果・使った所。画像と指示の全文は置かない…ただし指示の雛形は ADR に公開済み)を入れる**。PD / CC0 の参考は、出所の URL・作者・ライセンス・確かめた日と方法を記録に書く(`refs/pd/*.provenance.json` の形)。
4. 部品から導いたもの(当てはめた値、ベクター化した曲線)の記録は、**元の参考の id を持つ**(部品ごとの出所の記録)。

### D3. 整理とベクター化

- **整理**: 傾きと余白をそろえ、2 値化(輝度のしきい値)し、小さな点を除く。シートは 8 つのマスに分ける(マスの位置は固定の格子。ずれたら人が直す)。**生成された線画の線が二重・途切れのときの整理**(Simo-Serra の単純化など)は、v1 では使わない(その参考は捨てる)。
- **v1 の道具**: **potrace**(アルゴリズム。Python の `potracer` か、`potrace` の実行ファイル)で、暗い層の輪郭を少ないベジェに直す。マンガ風の顔は、太い線と塗りなので、輪郭のトレースで足りる(スパイク: 12.5 KB、352 区間)。細い 1 本の線(鼻、口)が二重の輪郭になる所は、段 a のランドマークと段 b の評価には問題ない。
- **中心線のベクター化**(Favreau 2016 / Noris 2013 / Bao と Fu 2023 / Deep Sketch Vectorization 2024)は、**v2 の選択肢**。1 本の線として、線の太さと位置を別に扱いたくなったとき(眉・まつげの太さの分布を取るときなど)に調査する。色の当てはめ(DiffVG / LIVE)は、v1 の範囲外。
- ベクター化の結果も**参考の一部**で、記録に元の id を持つ(出荷の規則は D6)。

### D4. 部品の分け方

- **v1: 人が打つ約 20 点のランドマーク**(あご・頬・耳・目の角と上下・眉・鼻先・口・頭頂)。点の名前と意味は `tools/fit/landmarks.ts`(モデルの側の定義)と、参考ごとの `*.landmarks.json`(参考の側の座標)で揃える。1 枚のシートで 8 表情 × 20 点 = 160 点。道具は、ブラウザの 1 ページ(画像に点を打って JSON に書く。R4)。
- 自動の検出器(アニメ顔のランドマーク検出モデル)は、**モデルの学習データとライセンスが不明なので、v1 では使わない**。
- 部品ごとの切り出し(目・口の画像)は、ランドマークから作る(目の矩形など)。髪は、ランドマークの外側の暗い層のシルエット(ベクター化の結果)。

### D5. 当てはめは 2 段

- **段 a: ランドマークの最小二乗**(決定的)。比と位置(あごの深さ、頬の幅、目の位置・幅・高さ・間隔、口の位置と幅、眉の高さ)を当てる。未知数は、画像 → モデルの写像(拡大率と平行移動)と、モデルのパラメータ。**与えられたパラメータでは、写像は閉じた形(重みつきの相似変換)で解ける**ので、探索はパラメータだけ。モデルが刻みに丸めるので、勾配の代わりに**刻みの格子上の座標降下**(スパイク)。ランドマークに重みを付ける(頭頂・耳は軽く)。出力は、パラメータ・写像・ランドマークごとの残差。
- **段 b: 見た目の当てはめ**(目の形、髪の外形)。**v1 は CMA-ES(導関数なしの最適化)**。損失は、参考の**インクの縁の距離変換**に対する、モデルの線(`faceFragment` のパスを折れ線にした点列)の chamfer 距離(両方向の平均)。**ラスタに描かずに、折れ線の点で距離変換を引く**ので、速く決定的(スパイクはラスタ化した縁で試した)。パラメータは、目(`w` `h` `tilt` `iris` `lidW`)、髪(毛束の数・分け目・側面の長さ)。**DiffVG / LIVE は使わない**(モデルを微分可能に書き直す費用が大きい。色も v1 の範囲外)。
- **丸め(刻み)**: 当てはめた値は、モデルの刻みに丸めたもの(モデルが出せる値)。範囲の外に出たものは、範囲の端に張り付いた印を付けて出力する(スパイク: 5/9)。

### D6. 当てはめの結果の使い方と、出荷の規則(ADR 0001 D6 の改訂)

**ADR 0001 D6 の改訂**: 生成モデルの出力は、「出荷する絵」としては引き続き許さない。**「当てはめの参考」としては、この ADR の規則の下で許す**。ADR 0001 の D6 の本文に、この ADR への注を足した(同じ PR)。

1. **パラメータの範囲とプリセット**(当てはめた値の分布から作る): **出荷してよい**。数(比・位置・大きさ)は、特定の絵の形ではない。生成した参考(AI)・PD / CC0 のどちらの参考に由来してもよい。ただし、**1 枚の参考に由来する値を、そのまま 1 人の既定の人物にしない**(分布の統計(範囲・中央値・四分位)として使う。特定の参考に似た人物を、出荷物にしない)。
2. **残差**(当てはめの足りない所): モデルの改良の入力にする。**参考の形をそのまま取り込まない**(足りない自由度を、私たちの言葉(パラメータ)で足す)。
3. **髪のテンプレート**(いちばん鋭い問題。髪の外形は、形そのものが絵):
   - **出荷してよい**: **PD / CC0 の参考**(出所の記録のある、国立国会図書館の `pdm`、OpenGameArt の CC0 を 1 点ずつ確認したもの、Wikimedia の PD-old)の暗い層をトレースし、整理した曲線から作った髪の外形。記録に元の id と、整理の手順を書く。
   - **出荷しない**: **生成した参考(AI)の曲線**は、整理・単純化・平均化しても、テンプレートの形として出荷しない。**パラメータ(毛束の数、側面の長さ、量の偏り、分け目の位置の分布)を通してだけ、髪のテンプレートに影響する**。髪の外形は、私たちのコード(幾何の説明から書いたもの。ADR 0001 D6)で書く。
   - 理由: 生成した画像の権利は不確かで(出力の権利・学習データの由来・既存の絵への類似)、曲線そのものが出荷物に入ると、類似の検査(人の目)が最後の砦になる。PD / CC0 は、権利が確かで、出所を記録できる。**これは owner の判断(Q2)**。
4. **出荷する絵は、常にパラメータから描き直したもの**(`faceFragment`)。参考の画像、ベクター化した曲線(PD / CC0 を除く)、非公開の置き場の中身は、パッケージにも公開リポジトリにも入らない。
5. **使ってよい PD / CC0 の出どころ**: 国立国会図書館の `pdm`(パブリックドメインのマーク)の資料、OpenGameArt の CC0 の肖像(**1 点ずつ**ライセンスを確かめる。作者の名前・URL・日付を記録)、Wikimedia の PD-old。**Wikimedia Commons の CC0 / PD は、1 点ずつ、ページのメタデータとテンプレートで確かめる**(スパイクの手順。`licence_checked` に方法を書く)。**著作権のある絵、出所の不明なスクレイプのデータセット、ライセンスを確かめていない絵は、使わない**。
6. **記録のない参考は使わない**(`PROVENANCE.md` に行が無ければ、当てはめの入力に使えない。R2 のテスト)。

### D7. 道具の置き場

- **`tools/fit/`(Python)**。npm パッケージには入れない(`package.json` の `files` に含めない)。依存は `tools/fit/requirements.txt`(`numpy` `scipy` `pillow` `potracer`)。**モデルの数値は TypeScript(`src/`)が持ち、Python は `node tools/fit/*.ts` を呼んで取る**(式の二重化を避ける。スパイクの `landmarks.ts` / `render.ts`)。
- 出力は **JSON**(当てはめたパラメータ・残差・出所の id)。プリセットや範囲の更新は、人が見て PR にする(自動で `src/` を書き換えない)。
- 非公開の置き場(`cuzic/manga-face-refs`)は、**画像・記録・ランドマークの座標・ベクター化の曲線(AI の参考由来)**。公開リポジトリに入れるのは、記録の行(ハッシュ・結果)、PD / CC0 の参考とその派生、当てはめたパラメータ。

### D8. 品質の指標(ADR 0001 D7 に足す門)

見分けやすさ(Q10)とブラインド確認に、**参考との距離**を足す。**暫定。参考が 40 枚そろってから、分布で決め直す**。

| 指標 | 内容 | 暫定の目標(スパイクの値は 1 枚だけ) |
|---|---|---|
| 段 a の残差 | 当てはめ後のランドマークの RMS(モデルの座標。頭の円の半径を 100 とする)。参考ごと | **中央値 ≤ 6、最大 ≤ 10**(スパイク: 5.3、最大 11.5。若い方向の既定値のとき 11.0) |
| 範囲の端への張り付き | 当てはめた値が範囲の端に張り付く割合(参考全体) | **端に張り付く参考が 20% 以下**(スパイク: 9 個中 5 個。範囲を広げる根拠) |
| 見た目の残差 | 段 b の chamfer(顔の幅に対する %) | **中央値 ≤ 3%**(スパイク: 2.2%、ただし当てはめは段 a だけ) |
| 部品ごとの残差 | 目・眉・口・輪郭・髪の部品別の残差(ダッシュボード) | 上回る部品を、モデルの改良の優先にする |

出荷物(モデルの出力)が、**参考の分布の範囲に収まるか**も測る(範囲の外の人物を作れてしまうとき、範囲を絞るか広げる)。

### D9. 権利の線のまとめ

| 物 | 公開リポジトリ | 非公開の置き場 | 出荷物 |
|---|---|---|---|
| 生成した画像(AI) | 置かない(ハッシュと記録の行だけ) | 置く | 入れない |
| 生成した画像のベクター化・ランドマーク | 置かない | 置く | 入れない |
| AI の参考から当てはめたパラメータの統計(範囲・プリセット) | 置く(統計として) | 置く | 入れる |
| PD / CC0 の画像・ベクター化 | 置く(出所の記録つき) | — | 髪のテンプレートに限り、整理した曲線を入れてよい(記録つき) |
| 指示の雛形 | ADR に置く | — | — |
| API キー | **どこにも置かない**(環境変数だけ) | — | — |

## 代替案

| 案 | 採らない理由 |
|---|---|
| いまのまま、ゼロから設計する(ADR 0001 のみ) | 数値の目標(目の大きさ・顔の縦横比・髪の外形)の根拠が無い。見た目の評価が好みの往復だけになる |
| 生成した画像のベクター化した曲線を、そのままテンプレートにする | 権利が不確かで、類似の検査が人の目だけになる(D6 の 3) |
| 生成モデル(OmniSVG など)で SVG の部品を直接作る | 権利と類似の検査の問題が、出荷物に直接入る |
| 生成した画像をニューラルネットワークの学習に使う | この ADR の範囲外。画像 API の利用条件が学習への利用を制限しうる(Q6)。数少ないパラメータの当てはめで足りる |
| 参考を公開リポジトリに置く | 生成した画像の権利が不確か。非公開の置き場にする |
| 自動のランドマーク検出器 | 学習データとライセンスが不明。v1 は人が打つ(20 点 × 320 の顔 = 6,400 点。道具で 1 枚 10 分と見て、40 枚で約 7 時間。**代わりに、1 表情ごとに点を打たず、中立 1 つに 20 点 + 他の表情は差分(目・眉・口の 8 点)だけにして、40 枚で約 3 時間に減らす案**を R4 で試す) |
| DiffVG / LIVE で色まで当てはめる | モデルを微分可能に書き直す費用が大きい。色は範囲外 |

## 影響

- ADR 0001 の D6 に改訂の注を足した。AGENTS.md の権利の約束に、「ADR 0002 受理までは例外を使わない」と明記した。
- 公開リポジトリに、`tools/fit/`(Python)、`refs/pd/`(PD / CC0 の参考とその出所)、`docs/adr/0002-spike-*` が増える。**生成した画像は入らない**。
- 費用: 画像 API(D1 の見積り。実装前に価格表で確かめ、owner が上限を決める)。人の確認の手間(1 枚 数分、40 枚)。
- **この ADR が受理されるまで、API は呼ばず、非公開の置き場は作らない。**

## テスト方針

- API は呼ばない(模擬)。`tools/fit/` のテストは、PD の 1 点(`refs/pd/`)で、数値が固定の範囲に入ること。Python の依存は `requirements.txt` で固定し、CI の別ジョブで回す(`tools/fit` の変更があるときだけ)。
- 非公開の置き場の中身は、CI に渡さない。

## 決める人への質問

| # | 質問 | 推奨 | 理由 |
|---|---|---|---|
| Q1 | 非公開の置き場を作る時期と名前 | **この ADR の受理後に、`cuzic/manga-face-refs`(非公開)を作る**。画像と記録・ランドマーク・AI 由来のベクター化を置く。公開リポジトリには出所の記録の行と PD / CC0 だけ | 受理前に作ると、方針が変わったときの片付けが要る |
| Q2 | **髪のテンプレートの出荷の規則(いちばん鋭い問題)** | **PD / CC0 の参考からトレースした曲線は、記録つきで出荷してよい。生成した(AI の)参考の曲線は、整理しても出荷しない。パラメータの分布を通してだけ影響させる**(D6 の 3) | 生成物の権利が不確かで、曲線が出荷物に入ると類似の検査が人の目だけになる。PD / CC0 は権利が確かで出所を記録できる。**もっと緩める(AI の曲線を、複数枚の平均にして出荷)案や、もっと絞る(髪も出荷しない。パラメータのみ)案は、owner が選べる** |
| Q3 | 生成の予算の上限と、最初の規模 | **最初は 10 枚(約 $5 以内)で、人の確認の手間と採用率を測ってから、40 枚へ**。上限は owner が決める。生成の前に費用を表示して `--yes` を要する | 価格は変わるし、採用率が分からない |
| Q4 | 確認する人 | **owner が最終。Claude は下見の一覧表(捨てる基準の自己点検)を作るが、似ているかの判断は人** | 類似の判断は権利の最後の砦 |
| Q5 | 参考の枚数(v1) | 40 枚(320 の顔)。PD / CC0 はあるだけ(10 点ほど) | 範囲と分布を作るのに足りる最小。端の張り付きの割合が測れる |
| Q6 | OpenAI の利用条件の確認 | **実装(R1)の前に、owner が、出力の利用(参考にだけ使い、画像を出荷しない、ニューラルネットワークを学習しない)が、そのときの利用条件に合うかを確認する**。条件の URL と確認日を ADR に記録する | 条件は変わる。出力の権利と、学習への利用の制限を確かめる |
| Q7 | PD / CC0 の出どころの許可リスト | NDL の `pdm`、OpenGameArt の CC0(1 点ずつ確認)、Wikimedia の PD / CC0(1 点ずつ)。それ以外は、owner の許可を取る | 出所を記録できるものだけ |
| Q8 | ランドマークを打つ道具 | ブラウザの 1 ページ(中立 1 つに 20 点 + 他の表情は差分)。点の数と手間は R4 で測り、多すぎれば減らす | v1 は人が打つのが現実的 |
| Q9 | 段 b の v1 | CMA-ES(折れ線の chamfer)。DiffVG / LIVE は使わない | モデルの数が少ない。丸めのある評価でも使える |
